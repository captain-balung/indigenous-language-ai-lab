# 部落大小事（情境應用 MISSION 01）

三個生活場景，一句一句輪流說的對話。其中一兩個角色由系統代說，換你說另一個。教材是「族語 E 樂園」互動模組／中級：溝通式教學法，42 個方言別都有。

沒有配分。每一句都會顯示系統聽到的、系統懂成的中文，以及教材怎麼講；失敗（辨識或翻譯中斷）不判錯。結果只存在當次頁面，不寫入瀏覽器儲存。

## 三個場景

| 場景 | 官方主題 | 對話角色 | 可扮演的角色 | 每方言輪數 |
| --- | --- | --- | --- | --- |
| 開學第一天 | 上課用語（`lesson`） | 同學、主角 | 主角 | 9 |
| 家裡辦婚禮 | 尋找物品（`find`） | 同學、媽媽 | 媽媽 | 8 |
| 週末想出門 | 戶外活動（`outside`） | 主角、哥哥、媽媽 | 哥哥、媽媽 | 7 |

角色清單不是寫死的，而是從教材每個主題的 `characters` 讀出來——「週末想出門」是三人對話，
所以那個場景有兩個角色可選。

**開場說第一句的角色不開放扮演。** 開場白前面沒有任何台詞可以接，學者只能憑空猜一句
（例如「媽媽今天家裡來了好多親戚哦！」），後面整段都掛在這個猜測上。
所以永遠由對方先開口，你扮演的一定是會回應的角色；介面會寫明「對話由○○先開口，你接著回應」。
只有一個可扮演角色時直接固定顯示，不做成看起來能點的按鈕。

## 作答

1. 選語言別與方言別，再選場景與角色（角色一律是會回應的角色）。
2. STEP 1 選完就收起來，STEP 2 只留這段對話；想改設定按「回到設定」，語言別、場景與角色會保留。
3. STEP 2 是遊戲式舞台：場景圖維持教材原本的比例、不拉伸不裁切（`object-fit: contain`），
   對話卡半透明地壓在場景下方（左邊立像、右邊台詞，「再聽一次」與「下一句 ▶」同一列）。
   **1201px 以上**左邊場景、右邊輸入區，場景填滿左邊剩下的空間（上限 1000px）；
   **1700px 以上**才改成對稱三欄「空白 / 場景 / 空白＋輸入區」，讓場景落在整個面板的
   **正中央**。兩種模式都在正常流程裡，輸入區會撐高面板、不會溢出；欄寬固定，
   所以從對方說話到換你說，背景的大小與位置不變。
   1200px 以下（含平板與手機）全部上下疊，場景用滿版寬。
   對方的錄音會自動播放，**播完（或播不成）才會出現「下一句 ▶」**，不強迫你等音檔。
4. 輪到你時打字或錄音送出。**換你說的那一句不會先顯示教材中文**，先看到等於看到答案；
   場景區只提示現在該做什麼（例如「用族語說出自己的名字或來處」「接著媽媽的話，用族語回應」）。
   送出後才顯示系統聽到的、系統懂成的，以及教材族語與教材中文。
5. 錄音會先辨識成文字，再翻成中文。麥克風沒權限或找不到麥克風時只在錄音列說明原因，
   這一句不會被判定或結束，改用打字即可繼續。
6. 最後看這輪的結果，可以換場景、換角色或換方言別再練。

## 任務關卡（STEP 4）

「開學第一天」練完對話後可以接著玩任務關卡（官方互動模組的 `phase2`）。**三個場景都有**，
但玩法不同：上課用語是「拖名牌」，尋找物品與戶外活動是「問人拿線索 → 在場景裡挑出正確的東西」。

| 場景 | 關數 | 過關條件 |
| --- | --- | --- |
| 開學第一天 | 5 | 問名字 → 放名牌；問住處 → 放地名；借筆／借橡皮擦／拿掃把要問對的人 |
| 家裡辦婚禮 | 5 | 挑出新的陶壺 → 摘月桃（**要先問對的人才拿得到**）→ 挑兩堆檳榔 → 點門 → 結語 |
| 週末想出門 | 4 | 把兩樣東西放進購物籃 → 挑對往溪邊的路 → 選要感謝的人並說出那句話 → 結語 |

**官方原本是拖詞卡拼句子，這裡換成自己說。** 詞卡（`hintWords`）直接送出了答案的詞彙**和順序**，
所以詞卡只留在「看提示」按鈕後面當字彙提示，不給順序；句子要學者自己錄音或打字說出來。
「選對的人並說出那句話」那一關，官方是把詞卡拖成句子，我們直接改成說出那句話（判定比對 `goal.prompt`）。

流程：先點一位同學（可點範圍對準官方 PNG 裡人物實際畫的位置），再錄音或打字送出，
對方的回答會留在畫面上（名牌要從「誰說了哪個名字」認出來），然後依關卡做對應的動作：

- **問對的人**：對指定那位問出指定那句就過關，桌上會出現那支筆／橡皮擦／掃把。
- **放名牌**：問完兩人才放出五張候選名牌，先點名牌再點同學放上去；**放對才固定，放錯可以再換**
  （放錯若也記下來，那張錯名牌會把位置鎖死、整關就卡住了）。
- **選東西**：右欄列出候選，點對就過關。
- **放進籃子**：點場景裡的東西放進右欄的籃子，按「確定」才判對錯，順序不影響結果。
  籃子裡的東西**可以點出來換**（官方也是這樣）；窄螢幕時場景裡的東西只有 30 幾個像素寬
  （小到不好點），右欄會多給一列按鈕。
  進度寫「已放 N 樣，要 M 樣」而不是「N/M」——籃子滿了不等於答對，寫成 N/M 會讓人以為已完成。
- **被鎖住的東西**：要先問對的人才拿得到。這種關卡沒問到人之前，點它、按「確定」都會
  明確提示「先問問誰」，不會只說「東西不對」讓人一直換著按。
  每次籃子內容改變都會清掉上一次的結果訊息，否則東西已經放進去了、畫面卻還停在
  「東西不對」，看起來會像按哪個都錯。
- **點某個地方**：例如點門，點下去會換掉背景並播官方的收尾台詞。
- **結語**：沒有互動，顯示官方的收尾文字。

輸入面板（錄音、翻譯、判定）跟 STEP 2 共用同一個，進任務時搬到任務畫面、回來時搬回去，
所以不會有兩套語音邏輯。任務不像對話要一句一句往下走，答錯不鎖住，隨時可以重說。

### 任務多了一條判定：這句要問對的人

官方 `player` 句型帶 `only` 標記，表示這句只能對某一個人說；對其他人說官方會判成答錯
（第 3 關「Kacaw 借我筆」只能問 Kacaw，問 Panay 不算）。所以判定多一種結果：

- **這句要問別人**：句子本身是對的，但對象不對，會提示換個人再問一次。
  第 1、2 關兩位同學要說的是同一句，那種情況不會誤報成「說錯人」。

## 官方資料的缺陷與處理

收錄 `phase2` 時發現幾處上游問題，都在下載時修掉並記在 `data/hordequest/dataset.json` 的 `notes`：

- **自我介紹的中文沿用別的名字**（6 個方言 7 處，例：茂林魯凱語的名字是 `Kukui`，中文卻寫「我的名字叫Kacaw。」）。
  寧可只留族語與錄音，也不要教錯名字，所以把該句中文收成 `null`。
- **`auto` 句在 `player` 清單裡找不到**（8 處，上游錯字，例：卑南語 40 第 4 關「aitrul maw」／「aitulr maw」）。
  官方玩到那關會得到「什麼？」、等於過不了關；改用同關同對象、帶錄音的那一句
  （回應索引 `code` 在全庫 328 句可完整比對的資料裡 100% 等於關卡序號，可以安全回推）。
- **句子比對忽略大小寫與多餘空白**：官方用嚴格比對，霧台魯凱語（28）因此玩不過。
- **任務說明有兩份**：官方頁面顯示的是共用的 `json/setup/{theme}.json`，方言別 JSON 裡另有一份變體。
  顯示用共用檔（文字比較乾淨），句子與過關條件用方言別的。
- **圖檔索引是「關卡序號 + 1」**：官方取圖寫的是 `img/{theme}/{關卡序號 + 1}-{物件}.png`
  （關卡序號從 1 開始，所以第 1 關取 `2-*.png`）。照字面組 `{關卡序號}-*.png` 會全部 404——
  一開始就是這樣，差點誤判成「官方沒有素材」。
- **對象的可點範圍官方沒有尺寸**：尋找物品與戶外活動的 `setup.target` 只給人的上角，
  官方 CSS 的 `.target` 也沒有寬高，所以那兩個主題的對象在官方是 0×0、根本點不到，
  連「問對人才解鎖」都走不到。這裡用官方人物 PNG 的不透明範圍量過的典型值補上寬高，
  並把 `right`／`bottom` 換算成 `left`／`top`，框才真的罩在人物上。
- **戶外活動第一關的第三個人**：官方把可點範圍設成 `width 0, height 0`，而且那個人剛好沒有
  這一句的回應（上游漏了一筆，42 個方言都一樣），所以這一關不提供他。
- 過關物件（筆／橡皮擦／掃把）不在 JSON 裡，對應關係來自官方 `quest-lesson.css` 的層名。
- **場景圖的副檔名依主題不同**（上課用語 `.jpg`、另外兩個主題 `.png`）。資料原本只存檔名、
  要靠呼叫端拼路徑，於是把另外兩個主題的對話背景都指到 `img/lesson/`、整片 404。
  現在存完整網址（`turns[].backgroundUrl`）。

## 鍵盤操作

- 按鈕都有 3px 粗邊框，瀏覽器預設的 focus 圈常常看不清楚，所以統一給
  `:focus-visible` 3px 的焦點圈（深色底的按鈕換成深藍）。用滑鼠點擊不會畫出來。
- 進入「換你說」時焦點自動移到輸入框；點名牌時焦點移到還沒放名牌的那位同學。
- `textarea` 保留 Enter 換行，所以沒有綁 Enter 送出。

## 參考句

只有兩種句子不判對錯：**報自己的名字**（「我叫X」）與**說自己的來處**（「我從X部落來」，
太魯閣語省略主詞寫成「X部落來」也算）。學者要說的是自己的名字跟自己的部落，
跟教材本來就不會一樣，這種句子標成參考句：照樣翻譯、照樣顯示教材，但不判對錯。

判斷只看中文參考答案有沒有這些字，**不看有沒有拉丁字母**。因為「Payu，明天是星期天，你打算去哪裡？」
開頭的「Payu」是稱呼學者自己、「我明天要和Lisin去溪邊烤肉」提到的是第三人，
這兩種正是學者該照教材說的內容，早先卻因為含拉丁字母被誤判成參考句（全庫誤判 84 輪）。

所以「開學第一天」的主角 4 句只比對 2 句（自我介紹與來處）。
「家裡辦婚禮」與「週末想出門」的每一句都會比對。
角色下面只寫要說幾句；不判對錯的句子等送出後才說明。

## 怎麼判定

情境對話不比對考試配分，只分四種：

- **說對了**：你說的族語去掉標點後與教材相同（羅馬字大小寫不帶意思，一律轉小寫比）。
- **意思對上教材**：系統懂成的中文，去掉標點與句末語助詞（「耶、呀、喔、呢、啦、嘛、啊」）後與教材中文相同。
- **再試試看**：兩者都對不上，會附上教材那句。
- **這次沒有判定**：辨識或翻譯失敗，不算答錯。

參考句固定顯示「參考句」，不進入上面四種判定。

## 舞台版面

參考官方互動模組的對話呈現：場景圖當背景，對話卡半透明壓在場景下方，左立像右台詞。

**任務關卡的呈現不一樣**：官方把詞卡區放在場景**下面**，所以桌面是空的，過關時那支筆才看得到。
我們的卡片是壓在場景上的，壓在下面會把桌面蓋掉，所以任務卡改放在場景**上方**，
兩位同學與主角都留在下半部，桌面留給過關的物件。

官方的人物是三層 1000×700 的透明整幅圖疊在場景上。圖層必須是按鈕的兄弟節點——
放進按鈕裡會被按鈕的盒子再縮放一次、位置也會往下偏。圖層與可點框還要相對「場景圖」定位
（包在 `.quest-scene` 裡）：窄螢幕時對話卡是排在圖的下面，`.stage` 會比圖高，
圖層用 `inset: 0` 就會被一起撐高，人物被畫偏、還蓋到下面的卡片上。

可點的透明按鈕框住那位同學，範圍是量過官方 PNG 的不透明範圍得到的
（target-1 left 2.5%、top 49.1%、寬 28.6%、高 50.7%；target-2 left 66.8%），
官方 CSS 寫的框比人物偏右上、也切到桌面。

場景面板比全站內容區（1040px）更寬（最多 1900px），否則場景會被容器上限壓得很小。
三個主題的場景圖比例略有不同（上課用語 1000×700、另外兩個 1000×707），一律用
`object-fit: contain` 讓圖保持自己的形狀。**但不能只靠 contain**：框的比例跟圖不一致時，
contain 會把圖縮到塞滿較窄的一邊、另一邊就留一圈空白邊（在框裡看得到圖以外的空白）。
所以圖載入後要用它自己的固有比例（`setSceneImage` 依 `naturalWidth/naturalHeight` 設
`aspect-ratio`），框才會剛好等於圖、貼滿外框。

同理，螢幕很矮時（`max-height: 640px`）要讓**高度**決定大小、寬度跟著等比縮小
（`width: auto` + `height: 240px`）；若維持 `width: 100%` 只壓高度，框會比圖寬得多、
左右各留兩百多像素的空白。

**置中與大小的取捨**：場景置中又要把輸入區放在右邊，兩者不重疊的條件是左右各留
(輸入區 + 間距) 一樣寬的空白，場景會因此少掉約 190px。所以只有場景本身夠大時才置中：
1700px 這個門檻是算出來的，在這個寬度置中的場景與填滿剩餘空間的場景一樣大
（都是 1000px 上限），從較窄切過來時不會突然變小。

配色與粗邊框沿用本站，不抄官方的黃藍配色。

## 語音辨識的限制

官方語音辨識只提供 16 個族級模型，沒有 42 個方言別模型。選了某個方言別時，送出辨識的是**該族的通用模型**，詞彙與音韻差異可能造成偏差。這是模型的限制，不代表你念錯。打字作答不經過語音辨識。

## 隱私

錄音會上傳到 `ai3.iformosa.com.tw` 辨識；教材音檔與場景圖由 `web.klokah.tw` 直接播放與熱連結，播放時該網站會看到你的 IP 位址。本站不儲存你的錄音，沒有帳號、沒有追蹤、沒有 cookie。請不要錄入個人資料。
