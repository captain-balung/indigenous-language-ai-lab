# 部落大小事（情境應用 MISSION 01）

三個生活場景的族語對話。STEP 2 只聽：每句自動播放並顯示台詞，按「下一步」才繼續（可不聽完）；不用開口回應。聽完直接進任務關卡（STEP 3）。教材是「族語 E 樂園」互動模組／中級：溝通式教學法，42 個方言別都有。

任務關卡沒有配分。結果只存在當次頁面，不寫入瀏覽器儲存。

## 三個場景

| 場景 | 官方主題 | 對話角色 | 每方言輪數 |
| --- | --- | --- | --- |
| 開學第一天 | 上課用語（`lesson`） | 同學、主角 | 9 |
| 家裡辦婚禮 | 尋找物品（`find`） | 同學、媽媽 | 8 |
| 週末想出門 | 戶外活動（`outside`） | 主角、哥哥、媽媽 | 7 |

角色清單來自教材每個主題的 `characters`（「週末想出門」是三人對話）。介面不再選角色——STEP 2 依序播完整段對話。

## 聽對話

1. 選語言別與方言別，再選場景（不用選角色）。
2. STEP 1 選完就收起來，STEP 2 只留這段對話；想改設定按「回到設定」，語言別與場景會保留。
3. STEP 2 是遊戲式舞台：場景圖維持教材原本的比例、不拉伸不裁切（`object-fit: contain`），
   對話卡半透明地壓在場景下方（左邊立像、右邊說話者與中文／族語台詞、「下一步」；沒有再聽／播放狀態按鈕）。
   1200px 以下（含平板與手機）全部上下疊，場景用滿版寬。
   每句錄音會自動播放，「下一步」一進句就顯示；按下才進下一句並播放（可不聽完就往下）。
4. 最後一句按「去任務」（有任務時）直接進任務關卡；沒有對話聽完的中間頁。

## 任務關卡（STEP 3）

聽完對話後可以接著玩任務關卡（官方互動模組的 `phase2`）。**三個場景都有**，
官方是選項／拖牌／拖詞卡，這裡全部換成「自己說」：先點人、說出那句話，後續動作
（放名牌、過關）由系統接手，互動的節奏與回饋跟官方一致。

| 場景 | 關數 | 過關條件 |
| --- | --- | --- |
| 開學第一天 | 5 | 問名字 → 名字自動上桌；問住處 → 地名自動上桌；借筆／借橡皮擦／拿掃把要問對的人 |
| 家裡辦婚禮 | 5 | 挑出新的陶壺 → 摘月桃（**要先問對的人才拿得到**）→ 挑兩堆檳榔 → 點門 → 結語 |
| 週末想出門 | 4 | 把兩樣東西放進購物籃 → 挑對往溪邊的路 → 選要感謝的人並說出那句話 → 結語 |

**官方原本是拖詞卡拼句子，這裡換成自己說。** 問句的意思沒對上時，那位同學會照官方
`phase2[target]["0"]`（`rebounds`）說出「不知道／什麼？」——回應錄音照播、話顯示在
任務卡的回應行，畫面上不會跳出「你答錯了」的判定卡。
詞卡（`hintWords`）直接送出了答案的詞彙**和順序**，
所以詞卡只留在「看提示」按鈕後面當字彙提示，不給順序；句子要學者自己錄音或打字說出來。
「選對的人並說出那句話」那一關，官方是把詞卡拖成句子，我們直接改成說出那句話（判定比對 `goal.prompt`）。

流程：先點一位同學（可點範圍對準官方 PNG 裡人物實際畫的位置；**被點選的同學會換上官方
`target-N-2.png` 的選中變體並帶光暈，主角圖也跟官方一起換向——問右邊的同學才換
`player-2.png`，問左邊維持 `player-1.png`**），再錄音或打字送出，然後依關卡做對應的動作：

- **問名字／問住處**：說對那句、聽到回應，官方 `complete.answers` 裡的名字（地名）就
  **自動放到那位同學的桌上**，不用再拖曳名牌。位置對準桌上那張空的名牌卡
  （字置中在卡上，跟桌上印好的名字同一擺法）；第 2 關的名字排在卡的左側成對，
  顏色照官方兩種卡色（card-1 棕、card-2 藍），字級與桌上印字同一套。
  **名字會累積**：第 1 關問過的名字到了第 2～5 關還留在桌上（官方同一個場景）。
  兩位都問到就過關。
  中間那一位是主角（你自己），場景上有一個「主角（就是你）」的小標示；
  主角自己的名字官方已印在桌牌上，不用再顯示。
- **問對的人**：對指定那位問出指定那句就過關，桌上會出現那支筆／橡皮擦／掃把。
  借筆只能問**左邊**的同學、橡皮擦只能問**右邊**的同學：不能問的那位會鎖起來
  （光標顯示禁止、進關就亮 `is-locked`），點了他不會選中，任務卡會提醒
  「這句要問○○，點錯人了」——提示直接叫第 1 關問到的**名字**（不用「右邊」這種位置詞）。
- **名字一直在桌上**：第 1、2 關問到的名字（含地名），到第 3、4、5 關都照官方
  一直留在桌上，不會因為換關卡就消失。
- **選東西**：右欄列出候選，點對就過關（判定播官方 right／wrong 音效，錯了可以再選）。
- **放進籃子**：點場景裡的東西放進右欄的籃子，按「確定」才判對錯（一樣播音效），順序不影響結果。
  籃子裡的東西**可以點出來換**（官方也是這樣）；購物清單可以收起／展開（官方也是這樣）。
  窄螢幕時場景裡的東西只有 30 幾個像素寬（小到不好點），右欄會多給一列按鈕。
  進度寫「已放 N 樣，要 M 樣」而不是「N/M」——籃子滿了不等於答對，寫成 N/M 會讓人以為已完成。
- **被鎖住的東西**：要先問對的人才拿得到。這種關卡沒問到人之前，點它、按「確定」都會
  明確提示「先問問誰」，不會只說「東西不對」讓人一直換著按。
  每次籃子內容改變都會清掉上一次的結果訊息，否則東西已經放進去了、畫面卻還停在
  「東西不對」，看起來會像按哪個都錯。
- **點某個地方**：例如點門，點下去會換掉背景並播官方的收尾台詞。這種關卡一進關就能點
  （官方也是），任務卡會讓到場景左下角，避免蓋住門。

## 過關的節奏與卡關輔助（對齊官方）

- **過關只留「下一關 →」**：條件一滿，右欄下方出現「下一關 →」鈕（最後一關是
  「看任務結果」），學者自己按了才往前；不用彈窗。「再玩一次」用關卡選擇排的那顆號碼重玩。
- **結語（end）**：沒有互動，官方收尾文字顯示在右欄的目標面板，下方接「下一關 →」。
- **答錯 3 次出現「自動說這句」**：同一關說錯累計 3 次（對錯人也算），會出現跟官方
  `autoask-btn` 一樣的出口——系統代學者把那句說出來（示範句錄音＋同學回應照播），
  關卡照樣往下走。
- **畫面上不顯示「對／錯」判定**：判定結果只有聲音與畫面變化——說對了會直接聽到
  回應、名字／過關物件會自己出現；select／take 的對錯照官方只有 right／wrong 音效。
  沒有「說對了／再試試看」的結果卡，也沒有「你答錯了」的提示；操作上的提醒
  （還沒問到人、籃子是空的）才會出現在任務卡那一行，那是「下一步」的指引不是判定。
- **判定的對／錯音效**：官方 `#right-sound`／`#wrong-sound`（`text/mp3/right.mp3`、`wrong.mp3`
  熱連結），在 select／take 的判定鍵上播。放名牌錯不播——官方放置時本來就沒有音效。

輸入面板（錄音、翻譯、判定）在 STEP 2 對話時隱藏；進任務時搬到任務畫面、回來時搬回去，
所以不會有兩套語音邏輯。任務答錯不鎖住，隨時可以重說。打字模式直接輸入教材的**中文**
那句（如「Panay借我橡皮擦好嗎」）只有**除錯模式**算過：網址加 `?debug_mode`
（一般學者的輸入不吃這條，也不依賴翻譯）。

### 說話任務的判定與 AI 語意補判

親自說出／打字送出的句子依序判定：族語（去標點、折疊大小寫）與教材句相同 → 說對了；
系統懂成的中文與教材中文相同 → 意思對上。兩者在規則裡都沒過時，再送自架 vLLM
（經 `/api/llm-complete`，`semantic-judge.mjs`）判一次「譯文與教材中文是不是同一個意思」
——同一件事就算意思對上（`semantic`）。LLM 失敗時維持本來的再試試看結果，判定不會
因此變嚴，同學回應行會加註「AI 判別暫時連不上」讓你知道是服務問題、不是 AI 聽不懂。
只送譯文與教材中文，不送參考族語句；錄音只送 Formosan。服務狀態列會顯示
「語意使用 vLLM AI 判別」。

### 任務多了一條判定：這句要問對的人

官方 `player` 句型帶 `only` 標記，表示這句只能對某一個人說；對其他人說官方會判成答錯
（第 3 關「Kacaw 借我筆」只能問 Kacaw，問 Panay 不算）。所以判定多一種結果：

- **這句要問別人**：句子本身是對的，但對象不對——對象不對照樣算沒對上，
  畫面不會多說什麼（同「不顯示對／錯」），換個人再問就會過。
  第 1、2 關兩位同學要說的是同一句，那種情況不會誤判成「說錯人」卡住。

## 官方資料的缺陷與處理

收錄 `phase2` 時發現幾處上游問題，都在下載時修掉並記在 `data/hordequest/dataset.json` 的 `notes`：

- **自我介紹的中文沿用別的名字**（6 個方言 7 處，例：茂林魯凱語的名字是 `Kukui`，中文卻寫「我的名字叫Kacaw。」）。
  寧可只留族語與錄音，也不要教錯名字，所以把該句中文收成 `null`。
- **`auto` 句在 `player` 清單裡找不到**（8 處，上游錯字，例：卑南語 40 第 4 關「aitrul maw」／「aitulr maw」）。
  官方玩到那關會得到「什麼？」、等於過不了關；改用同關同對象、帶錄音的那一句
  （回應索引 `code` 在全庫 328 句可完整比對的資料裡 100% 等於關卡序號，可以安全回推）。
- **句子比對忽略大小寫與多餘空白**：官方用嚴格比對，霧台魯凱語（28）因此玩不過。
  例外：賽夏／噶瑪蘭的大小寫是正寫法的一部分（賽夏大寫 S、噶瑪蘭大寫 R），
  兩族嚴格比對、只容忍 ASR 在句首補大寫的慣例（見 `core.mjs` 的 `indigenousKey`／`sameIndigenousKey`）。
- **任務說明有兩份**：官方頁面顯示的是共用的 `json/setup/{theme}.json`，方言別 JSON 裡另有一份變體。
  顯示用共用檔（文字比較乾淨），句子與過關條件用方言別的。
- **圖檔索引是「關卡序號 + 1」**：官方取圖寫的是 `img/{theme}/{關卡序號 + 1}-{物件}.png`
  （關卡序號從 1 開始，所以第 1 關取 `2-*.png`）。照字面組 `{關卡序號}-*.png` 會全部 404——
  一開始就是這樣，差點誤判成「官方沒有素材」。
- **對象的可點範圍官方沒有尺寸**：尋找物品與戶外活動的 `setup.target` 只給人的上角，
  官方 CSS 的 `.target` 也沒有寬高，所以那兩個主題的對象在官方是 0×0、根本點不到，
  連「問對人才解鎖」都走不到。這裡用官方人物 PNG 的不透明範圍量過的典型值補上寬高，
  並把 `right`／`bottom` 換算成 `left`／`top`，框才真的罩在人物上。
- **戶外活動第一關的第三個人**：官方把可點範圍設成 `width 0, height 0`，而且那個人剛好沒有
  這一句的回應（上游漏了一筆，42 個方言都一樣），所以這一關不提供他。
- 過關物件（筆／橡皮擦／掃把）不在 JSON 裡，對應關係來自官方 `quest-lesson.css` 的層名。
- **場景圖的副檔名依主題不同**（上課用語 `.jpg`、另外兩個主題 `.png`）。資料原本只存檔名、
  要靠呼叫端拼路徑，於是把另外兩個主題的對話背景都指到 `img/lesson/`、整片 404。
  現在存完整網址（`turns[].backgroundUrl`）。

## 鍵盤操作

- 按鈕都有 3px 粗邊框，瀏覽器預設的 focus 圈常常看不清楚，所以統一給
  `:focus-visible` 3px 的焦點圈（深色底的按鈕換成深藍）。用滑鼠點擊不會畫出來。
- `textarea` 保留 Enter 換行，所以沒有綁 Enter 送出。

## 任務怎麼判定

任務關卡不比對考試配分。族語去掉標點後與教材相同算說對；系統懂成的中文去掉標點與句末語助詞後與教材中文相同也算過。辨識或翻譯失敗不算答錯，可以按「重試判定」再送一次。

## 舞台版面

參考官方互動模組的對話呈現：場景圖當背景，對話卡半透明壓在場景下方，左立像右播控（不顯示台詞文字）。

**任務關卡的呈現不一樣**：官方把詞卡區放在場景**下面**，所以桌面是空的，過關時那支筆才看得到。
我們的卡片是壓在場景上的，壓在下面會把桌面蓋掉，所以任務卡改放在場景**上方**，
兩位同學與主角都留在下半部，桌面留給過關的物件。

官方的人物是三層 1000×700 的透明整幅圖疊在場景上。圖層必須是按鈕的兄弟節點——
放進按鈕裡會被按鈕的盒子再縮放一次、位置也會往下偏。圖層與可點框還要相對「場景圖」定位
（包在 `.quest-scene` 裡）：窄螢幕時對話卡是排在圖的下面，`.stage` 會比圖高，
圖層用 `inset: 0` 就會被一起撐高，人物被畫偏、還蓋到下面的卡片上。

可點的透明按鈕框住那位同學，範圍是量過官方 PNG 的不透明範圍得到的
（target-1 left 2.5%、top 49.1%、寬 28.6%、高 50.7%；target-2 left 66.8%），
官方 CSS 寫的框比人物偏右上、也切到桌面。

場景面板比全站內容區（1040px）更寬（最多 1900px），否則場景會被容器上限壓得很小。
三個主題的場景圖比例略有不同（上課用語 1000×700、另外兩個 1000×707），一律用
`object-fit: contain` 讓圖保持自己的形狀。**但不能只靠 contain**：框的比例跟圖不一致時，
contain 會把圖縮到塞滿較窄的一邊、另一邊就留一圈空白邊（在框裡看得到圖以外的空白）。
所以圖載入後要用它自己的固有比例（`setSceneImage` 依 `naturalWidth/naturalHeight` 設
`aspect-ratio`），框才會剛好等於圖、貼滿外框。

同理，螢幕很矮時（`max-height: 640px`）也要用「寬」當上限：圖寬 `min(341px, 92vw)`
（341px ⇔ 上課用語高約 240px、另外兩個主題高約 241px），盒子的寬跟圖的寬用同一個上限
、高度照圖的固有比例走。若壓「高度」（`height: 240px` + `width: auto`），場景盒這個
block 的寬還是會佔滿欄位，盒會比圖寬、左右各留兩百多像素的空白；
名牌、同學、可點框都是相對盒子用百分比定位，盒子跟圖撐開座標就整組跑掉
（盒寬也不能用 `fit-content`——`.quest-scene` 是 `container-type: inline-size`，
大小不得依內容決定，`fit-content` 會解成 0；長度裡用 % 也會盒跟圖互相參照解成 0）。

桌上（印好的）名牌的字級要跟著場景寬度等比縮：官方在 1000px 舞台上是 `1.2em`（≈14.4px，
＝場景寬的 1.45%）、手機是 `1.6vw`。這裡用 container query 上限 `max(7px, 1.45cqw)`
（放上去的學習者名牌是 `max(8px, 1.9cqw)`）。字級寫死時場景一小，相鄰兩個名字疊在一起
（長名字如中排灣的「djiniljepan」）；7px 的下限是可讀性取捨，換來的是在最小的手機寬度上
，最長的兩個名字仍會輕微相疊——官方在該寬度也一樣疊（官方是 1.6vw，比我們的下限更小）。

另外官方座標是「字的左上角」，字會貼在卡片左緣、長名字整個伸出卡外；app 把每個字
移到那張藍卡的幾何中心（`app.mjs` 的 `DESK_TAG_CENTERS`，六張卡的位置是從場景與
人物圖層量出來的，42 個方言共用同一組錨點），配合 `translate(-50%,-50%)` 讓字置中，
長名字會左右對稱地稍微超出卡邊，像正牌的名牌卡。上游要是改了錨點座標，測試會擋下來。

**置中與大小的取捨**：場景置中又要把輸入區放在右邊，兩者不重疊的條件是左右各留
(輸入區 + 間距) 一樣寬的空白，場景會因此少掉約 190px。所以只有場景本身夠大時才置中：
1700px 這個門檻是算出來的，在這個寬度置中的場景與填滿剩餘空間的場景一樣大
（都是 1000px 上限），從較窄切過來時不會突然變小。

配色與粗邊框沿用本站，不抄官方的黃藍配色。

## 語音辨識的限制

官方語音辨識只提供 16 個族級模型，沒有 42 個方言別模型。選了某個方言別時，送出辨識的是**該族的通用模型**，詞彙與音韻差異可能造成偏差。這是模型的限制，不代表你念錯。打字作答不經過語音辨識。

## 隱私

錄音會上傳到 `ai3.iformosa.com.tw` 辨識；教材音檔與場景圖由 `web.klokah.tw` 直接播放與熱連結，播放時該網站會看到你的 IP 位址。本站不儲存你的錄音，沒有帳號、沒有追蹤、沒有 cookie。請不要錄入個人資料。
